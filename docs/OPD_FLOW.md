# Flow ผู้ป่วยนอก กับคิวห้องการเงิน

เอกสารนี้อธิบายว่า **ผังไหล OPD** ของโรงพยาบาลถูกแปลงเป็นเงื่อนไข query ใน
`lib/cashier.service.ts` อย่างไร — แก้ flow เมื่อไหร่ ให้กลับมาแก้ที่นี่กับ query คู่กัน

## flow บังคับอะไรกับ query บ้าง

| ข้อกำหนดจาก flow | เงื่อนไขใน query |
| --- | --- |
| **Admit = terminal** ไม่เข้าคิวการเงิน | `o.an IS NULL` |
| เอาเฉพาะคน **ที่ถูกส่งมาห้องการเงินแล้ว** ไม่ใช่ทุก visit ที่มีค่าใช้จ่าย | ดู "เกณฑ์เข้าคิว" ด้านล่าง |
| **คนมียาเข้าคิวการเงินหลังผ่านห้องยา** ไม่ใช่ทันทีที่ตรวจเสร็จ | เวลาส่ง + เกณฑ์เข้าคิวใช้ `service6` (ถึงห้องยา) สำหรับคนมียา |
| ER เข้าคิวการเงินได้เหมือนกัน (ผ่าน HosXP ส่งบริการ) | ไม่ได้กรอง `main_dep` ทิ้ง — ER ที่ถูกส่งมาก็ขึ้นคิว |
| **หลังชำระ: ไม่มียา → กลับบ้าน / มียา → กลับไปรับยา** | ฟิลด์ `route` → ป้าย "จ่ายแล้วรับยา / จ่ายแล้วกลับบ้าน" บนจอ |
| คนที่ **สิทธิ์เบิกได้เต็ม ไม่ต้องจ่ายเอง** ไม่ควรค้างบนจอ | ใช้ `vn_stat.remain_money` เป็นตัวตัดสินยอดค้าง |

## เกณฑ์เข้าคิว 2 แบบ

### แบบที่ 1 (แนะนำ) — ตั้ง `CASHIER_DEP_CODES`

```sql
WHERE q.cur_dep IN (<รหัสห้องการเงิน>) OR q.paid_money > 0
```

ตรงกับ flow ที่สุด เพราะทั้ง 3 ทางที่เข้าห้องการเงิน (ER · ไม่มียา · ห้องยาส่งรายชื่อ)
จบด้วยการที่ HosXP ส่ง visit มาที่ **แผนกห้องการเงิน** เหมือนกันหมด
หา depcode ได้จาก `docs/sql/cashier_queue.sql` ข้อ 1

### แบบที่ 2 (fallback) — ไม่ได้ตั้ง `CASHIER_DEP_CODES`

เดาจากเวลาจุดบริการใน `service_time` แทน

```sql
WHERE (q.has_drug = 0 AND q.after_doctor IS NOT NULL)   -- ไม่มียา: ตรวจเสร็จ = ส่งมาการเงิน
   OR (q.has_drug = 1 AND q.at_pharmacy  IS NOT NULL)   -- มียา: ถึงห้องยาแล้ว
   OR q.paid_money > 0
```

⚠️ แบบที่ 2 **หลวมกว่า** — คนมียาจะขึ้นคิวตั้งแต่เพิ่งถึงห้องยา ทั้งที่ห้องยาอาจยังจัดยาไม่เสร็จ
ใช้ชั่วคราวตอนยังไม่รู้ depcode เท่านั้น รู้แล้วให้ตั้ง `CASHIER_DEP_CODES` ทันที

## มียา / ไม่มียา ตัดสินอย่างไร

```sql
EXISTS (
  SELECT 1 FROM opitemrece oi
  INNER JOIN drugitems di ON di.icode = oi.icode
  WHERE oi.vn = o.vn
)
```

inner join กับ `drugitems` ทำให้เหลือเฉพาะ **รายการยาจริง** (ตัด Lab / X-ray / ค่าบริการ ออก)
— แนวเดียวกับ `lib/drugUsage.service.ts` ของ ppc-hos-10667

## จุดที่ flow ยังไม่ถูกนำมาใช้

- **Pre-registration / Triage / ห้องบัตร / ซักประวัติ / หน้าห้องตรวจ** — เป็นขั้นตอน
  *ก่อน* ห้องการเงิน ไม่มีผลกับคิวนี้ (นอกจากทำให้ยังไม่เข้าคิว)
- **รับบัตรนัด** — เป็นขั้นตอนเสริม ไม่เปลี่ยนเส้นทางไปห้องการเงิน จึงไม่ได้แยกไว้
- **ระบบคิว Hygge** — คนละระบบกับ dashboard นี้ ยังไม่ได้เชื่อมต่อ

## เลขคิว กับ ลำดับบนจอ

**เลขคิวบนจอ = `ovst.oqueue`** ซึ่งเป็นเลขเดียวกับที่จอคิวเดิมของ รพ. ใช้
(เดิม dashboard นับ 1–10 เอง จึงไม่ตรงกับจอเดิม — แก้แล้ว)

`oqueue` เป็น **integer ล้วน** (เช่น `39`) — `0` หรือ `NULL` = visit นั้นไม่ได้ออกเลขคิว
จอจะเว้นว่างไว้แทนที่จะขึ้น "คิว 0" และดันแถวนั้นไปท้ายคิว

**ลำดับการเรียง = `pt_priority` มาก→น้อย → เวลาที่ถูกส่งมา → `oqueue`**
ยกมาจาก `order by` ที่ HOSxP ใช้เองในหน้าคิวห้องยา (ดูหัวข้อ ★ ด้านล่าง)

- `pt_priority` = ผู้ป่วยเร่งด่วน/สูงอายุ ที่เจ้าหน้าที่ตั้งไว้ใน HOSxP → ขึ้นก่อน
- ที่เหลือเรียงตาม **เวลาที่ถูกส่งมาห้องเก็บเงิน** ไม่ใช่เลขคิว — ยืนยันจากการเทียบ
  รูปถ่ายจอเดิม (`oqueue 64` อยู่ท้ายคิวเพราะเพิ่งถูกส่งมาตอน 11:19)
- `oqueue` ใช้เป็นตัวตัดสินเฉพาะตอนเวลาซ้ำกันเป๊ะ

**เวลาที่ถูกส่งมาห้องการเงิน** ใช้ `ovst.cur_dep_time` (เวลาที่เข้าแผนกปัจจุบัน)
เป็นอันดับแรก แม่นกว่า `service_time` เพราะเป็นเวลาที่ HosXP ส่ง visit เข้าแผนก
ห้องการเงินตรง ๆ ถ้าไม่มีค่อยไล่ลงไปที่ `service6` → `service12` → `vsttime`

## ใครคือ "คนที่ถึงคิว"

**หัวแถวหลังเรียงลำดับข้างบน** — คนที่ยังไม่ชำระและถูกส่งมาห้องเก็บเงินก่อนใคร
(หรือคนที่ `pt_priority` สูงกว่า)

จอไฮไลต์คนหัวแถว และ **ประกาศชื่อเมื่อหัวแถวเปลี่ยน** — พอเจ้าหน้าที่รับเงินคนหน้าเสร็จ
HOSxP บันทึก `rx_operator.pay='Y'` และย้าย `cur_dep` ออกจากห้องเก็บเงิน คนนั้นหลุดจากคิว
หัวแถวเลื่อน จอจึงประกาศคนถัดไปเอง โดยไม่ต้องมีใครกด

**ไม่เดาจากคอลัมน์อื่น** — `finance_lock`, `remain_money`, `paidst` ไม่ถูกใช้ตัดสิน
ว่าใครจ่ายเสร็จแล้ว เพราะความหมายต่างกันในแต่ละ รพ. (และของ รพ. นี้เป็น 0 ทั้งตาราง)
ใช้ `cur_dep` + `rx_operator.pay` เท่านั้น

⚠️ **ห้ามใช้ `cur_dep = ห้องการเงิน` มาตัดสินว่า "กำลังชำระ"** — `cur_dep` บอกแค่ว่า
HosXP ส่งคนไข้มาเข้าคิวห้องการเงินแล้ว ซึ่งเป็นจริงกับ *ทุกคน* ในคิว ถ้าใช้เกณฑ์นั้น
ทุกคนจะขึ้นเป็น "กำลังชำระ" พร้อมกันหมด (บั๊กนี้เคยมีจริงและถูกแก้ไปแล้ว)

## ใครต้องมาจ่ายเงินที่ห้องการเงิน

ยึด **`opd_opi_finance_summary`** ซึ่งแยกยอดตาม `pttype.paidst`

| paidst | ความหมาย | คนไข้จ่ายเองไหม |
| --- | --- | --- |
| `00` | ค้างชำระ | – |
| `01` | ชำระเองเบิกได้ | ✅ จ่ายเอง |
| `02` | ลูกหนี้สิทธิ | ❌ เรียกเก็บจากกองทุน |
| `03` | ชำระเองเบิกไม่ได้ | ✅ จ่ายเอง |
| `04` | ส่วนลดเงินสด | – |

**ยอดที่ต้องมาจ่าย = `total_balance_01 + total_balance_03`**

```
รอชำระ   = total_balance_01 + total_balance_03 > 0   → ขึ้นจอ
ชำระแล้ว = 0 แต่ total_clear_01 + total_clear_03 > 0 → นับใน "ชำระแล้ววันนี้"
ไม่เกี่ยว = ไม่เข้าทั้งสองเงื่อนไข                     → ไม่ขึ้นจอเลย
```

### คอลัมน์ที่ลองแล้วใช้ไม่ได้

| คอลัมน์ | ทำไมใช้ไม่ได้ |
| --- | --- |
| `vn_stat.remain_money` | **เป็น 0 ทั้ง 264 visit** ในวันที่ตรวจ — เป็นช่องลูกหนี้ค้างชำระ ไม่ใช่ยอดที่ยังไม่จ่ายของวัน ถ้าใช้ตัวนี้จอจะว่างเปล่า |
| `vn_stat.income - paid_money` | ไม่หักสิทธิ์ — คนที่กองทุนจ่ายให้ทั้งหมดจะค้างบนจอทั้งวัน (261 จาก 264 visit) |
| `opd_opi_finance_summary.balance_amount` | รวมลูกหนี้สิทธิ (`02`) เข้ามาด้วย คนไข้กลุ่มนี้ไม่ต้องมาจ่าย |

## ตารางสถานะที่ HOSxP มี (และทำไมไม่ใช้)

`ovstost` มีสถานะทั้งหมด 28 รายการ — ตรวจแล้ว **ไม่มีสถานะที่เกี่ยวกับห้องการเงินเลย**

```
00 รอผลตรวจ · 01–14 Admit แผนกต่าง ๆ · 15 หนีกลับ · 16 ปฏิเสธการรักษา
17–19 เสียชีวิต · 52 ตายที่ OPD · 54 ส่งต่อ · 61–63 ตรวจรักษาที่…
98 รอรับยา · 99 ตรวจแล้ว
```

| ตาราง / คอลัมน์ | คืออะไร | ใช้ไหม |
| --- | --- | --- |
| `ovstost` | สถานะผู้ป่วย OPD | ❌ ไม่มีสถานะห้องการเงิน |
| `pttype.paidst` | สถานะการชำระของ**สิทธิ** | ✅ ใช้ทางอ้อมผ่าน `total_balance_01/03` |
| `ovst.finance_lock` | ไม่ทราบความหมายแน่ชัด | ❌ ไม่เอามาเดา |

สรุป: **ไม่มีตารางสถานะคิว** จึงยึด `oqueue` (ลำดับ) + ยอดที่ต้องจ่ายเอง (เข้า/ออกจอ)

## รหัสแผนกจริงของ รพ. (kskdepartment)

ยืนยันจากตารางจริงแล้ว — ใช้อ้างอิงเวลาแมป flow กับ `cur_dep` / `last_dep`

| depcode | แผนก | ตรงกับ flow ขั้นไหน |
| --- | --- | --- |
| `000` | ห้องบัตรเวชระเบียน | จุดที่ 2 ห้องบัตร (ตรวจสิทธิ์) |
| `001` / `062–064` | ซักประวัติ / ซักประวัติ 1–3 | จุดที่ 3 ซักประวัติ |
| `002–004`, `059` | ห้องตรวจ 1–3, ห้องตรวจ | จุดที่ 4 + พบแพทย์ |
| `009` | ห้องฉุกเฉิน | เส้นทาง ER |
| `008` | ห้องยา | มียา → ห้องยา |
| `060` / `061` | จ่ายยา ก / จ่ายยา ข | จุดจ่ายยา |
| **`013`** | **ห้องเก็บเงิน** | **ปลายทางของ dashboard นี้** |
| `029` | กลับบ้าน | จุดออกจากระบบ |
| `020` | ตึกผู้ป่วยใน | Admit (terminal) |

`CASHIER_DEP_CODES` ตั้งค่าเริ่มต้นเป็น `013` ไว้ในโค้ดแล้ว

### ทำไมต้องกรอง cur_dep = 013

1. เป็นนิยามที่ตรงที่สุดของ "คิวห้องเก็บเงิน" — HosXP ส่ง visit มาที่แผนกนี้เมื่อถึงคิว
2. ทำให้ `cur_dep_time` = **เวลาที่ถูกส่งมาห้องเก็บเงิน** ตามที่ต้องการพอดี
3. ทำให้ `last_dep` = **แผนกที่ส่งมา** (ห้องยา / ทันตกรรม / ฯลฯ) ซึ่งคือคอลัมน์บนจอ

**ห้ามถอยไปไม่กรองแผนก** — เคยทำแล้วพัง: ตอน 08:37 ยังไม่มีใครถึงห้องเก็บเงิน
(ถูกต้อง) แต่ระบบดันเอาคนที่เพิ่งลงทะเบียนที่ห้องบัตร 109 คนมาขึ้นจอว่า "รอชำระ"
ทั้งที่ยังไม่ได้พบแพทย์ จอว่างตอนเช้า = ถูกต้อง แสดง "ยังไม่มีคิว" แทน

## ★ สัญญาณ "จ่ายเงินเสร็จ" — ยืนยันจากหน้างานแล้ว

**เจ้าหน้าที่รับเงินเสร็จ → HOSxP ย้าย `ovst.cur_dep` ออกจาก `013 ห้องเก็บเงิน`**
(ไป `029 กลับบ้าน` หรือไปห้องยาถ้ามียา)

นี่คือคำตอบของคำถามที่ตามหามาหลายรอบ และมันง่ายกว่าที่คิดมาก

```
คิวรอ        = ovst.cur_dep IN (013)
จ่ายเสร็จ     = cur_dep ย้ายออกจาก 013  → หลุดจาก query ไปเอง
ผ่านไปแล้ววันนี้ = last_dep IN (013) AND cur_dep NOT IN (013)
คิวถัดไป      = หัวแถวของ oqueue ที่เหลือ → ประกาศชื่ออัตโนมัติ
```

### ผลที่ตามมา

- **โหมด `all` (ค่าเริ่มต้น) ไม่แตะตารางการเงินเลย** ไม่ต้องใช้
  `opd_opi_finance_summary`, `finance_summary_date`, `remain_money`, `paidst`
  ทั้งหมดที่ไล่หามาก่อนหน้านี้กลายเป็นทางเลือกเสริม (`QUEUE_SOURCE=charges/bill/selfpay`)
- **`QUEUE_MAX_AGE_MINUTES` ลดบทบาทเหลือแค่ตาข่ายกันเหนียว** เผื่อเจ้าหน้าที่ลืมกดปิด
  ใน HOSxP จึงยืดค่าเริ่มต้นจาก 120 เป็น 240 นาที ไม่ให้ไปตัดคนที่รอจริง
- **`CASHIER_DEP_CODES=013` กลายเป็นของจำเป็น** ไม่ใช่ตัวกรองเสริมอีกต่อไป
  เพราะทั้งการเข้าคิวและการออกจากคิวอาศัยคอลัมน์นี้ตัวเดียว

## ★★ ซอร์สโค้ดจอเดิม — เลิกเดา ใช้ของจริง

หน้างานส่ง `moneyAndDrug.php` + ไฟล์ `ajax/*.php` ของจอเดิมมาให้ ทุกอย่างในหัวข้อนี้
อ่านมาจากซอร์สนั้นตรง ๆ ไม่ใช่การตีความ

### ตารางหัวใจคือ `sd_queue_calling` (ไม่ใช่ `rx_operator`)

เจ้าหน้าที่กด "เรียกคิว" ใน HOSxP → INSERT แถวลง `sd_queue_calling`

| คอลัมน์ | ความหมาย |
| --- | --- |
| `sd_queue_calling_vn` | vn ของคนที่ถูกเรียก |
| `sd_queue_calling_hn` | hn |
| `sd_queue_calling_queue` | เลขคิว (= `ovst.oqueue`) |
| `sd_queue_calling_curdep` | depcode ของจุดที่เรียก |
| `sd_queue_calling_datetime` | เวลาที่กดเรียก |
| `sd_queue_calling_status` | `Y` = ยังไม่ได้ประกาศเสียง, ประกาศแล้วจอเดิม UPDATE เป็น `N` |

### รหัสแผนกห้องเก็บเงิน = `013`, `077`, `078`

จาก `moneyAndDrug.php` บรรทัด 291–292:

```js
setInterval(function() { getCurentVisit("'013','077','078'", 7); }, 3000);  // คิวรอ
setInterval(function() { getCurentQueue("'013','077','078'", 2); }, 3000);  // เรียกคิว
```

ห้องยาใช้ `'008','060','061'` — จอนี้ไม่เกี่ยว

### คิวรอ — `ajax/getScreeningW.php`

```sql
SELECT o.main_dep_queue, CONCAT(pt.pname, pt.fname, ' ', 'XXX') AS full_name,
       IFNULL(o.pt_priority,0) AS pt_priority, sc.*
FROM ovst o
LEFT JOIN ovstost ov ON o.ovstost = ov.ovstost
LEFT JOIN patient pt ON o.hn = pt.hn
LEFT JOIN sd_queue_calling sc
       ON o.vn = sc.sd_queue_calling_vn
      AND o.oqueue = sc.sd_queue_calling_queue
      AND sc.sd_queue_calling_curdep IN ('013','077','078')
WHERE o.vstdate = CURDATE()
  AND (o.cur_dep_time >= time(sc.sd_queue_calling_datetime)
       OR sc.sd_queue_calling_datetime IS NULL)
  AND o.cur_dep IN ('013','077','078')
ORDER BY o.cur_dep_time asc
LIMIT 7
```

**นี่คือคำตอบของ "ทำไมจอใหม่มีคนเกิน"** — คนที่ถูกเรียกไปแล้วต้องหลุดจากคิวรอ
ไม่เกี่ยวกับการจ่ายเงินเลย เงื่อนไข `cur_dep_time >= time(...)` เปิดช่องให้คนที่
**ถูกส่งกลับเข้าห้องอีกครั้งหลังถูกเรียก** กลับเข้าคิวได้ใหม่

สังเกตด้วยว่า **ไม่มี** `an IS NULL`, ไม่กรอง `ovstost`, ไม่แตะตารางเงินสักตัว
และเรียงด้วย `cur_dep_time` ล้วน — `pt_priority` เอาไว้ทำสีจุดเท่านั้น ไม่ได้ใช้เรียง

### เรียกคิว — `ajax/getDoctorRoomQ.php`

```sql
SELECT o.oqueue, o.hn, CONCAT(pt.pname, pt.fname, ' ', 'XXX') AS full_name,
       CONCAT('คุณ', pt.fname, ' ', pt.lname) AS full_namecall,
       sq.sd_queue_calling_status, department
FROM sd_queue_calling sq
INNER JOIN ovst o ON sq.sd_queue_calling_vn = o.vn
INNER JOIN patient pt ON o.hn = pt.hn
INNER JOIN kskdepartment d ON d.depcode = sq.sd_queue_calling_curdep
WHERE sq.sd_queue_calling_curdep IN ('013','077','078')
ORDER BY sq.sd_queue_calling_datetime DESC
LIMIT 2
```

แล้วประกาศเสียงเฉพาะแถวที่ `status = 'Y'` จากนั้น `UPDATE ... SET status='N'`
(ใช้ Google Translate TTS เป็น base64 ยัดใส่ `<audio autoplay>`)

⚠️ **บั๊กของจอเดิม** ไฟล์นี้ลืมใส่ `AND DATE(sq.sd_queue_calling_datetime) = CURDATE()`
ทั้งที่ `getMedicineQ.php` และ `getScreeningQ.php` ใส่ไว้ → เช้าวันใหม่จอจะยังค้าง
ชื่อคนของเมื่อวานจนกว่าจะมีคนถูกเรียกคนแรก **จอเราใส่เพิ่มให้แล้ว**

### สิ่งที่จอเราทำต่างจากจอเดิม (ตั้งใจ)

| | จอเดิม | จอนี้ |
| --- | --- | --- |
| เขียน `sd_queue_calling_status='N'` | เขียน | **ไม่เขียน** — จะได้ไม่แย่งกับจอเดิมตอนรันคู่กัน จอนี้ดูว่า "แถวล่าสุดเปลี่ยนไหม" แทน |
| ปิดนามสกุล | `'XXX'` ตายตัว | `ส●●●●` เหลืออักษรแรก |
| จำนวนคิวรอ | 7 | 10 (ตั้งได้ที่ `BOARD_ROWS`) |
| `DATE(...) = CURDATE()` ในเรียกคิว | ลืมใส่ | ใส่ |
| เวลารอ | `180 × ลำดับ ÷ 60` (ตัวเลขปลอม) | เวลาที่ถูกส่งมาจริง |
| TTS | Google Translate TTS | Web Speech API ในเบราว์เซอร์ |

### ของที่เลิกใช้แล้ว

- ~~`rx_operator.pay='Y'`~~ — เดาจาก SQL ห้องยา ผิด ตารางนี้เป็นของห้องยา
  คนไม่มียาไม่มีแถวเลย `NOT EXISTS` จึงไม่มีวันตัดใครออก
- ~~`opd_opi_finance_summary` / `remain_money` / `paidst` / `finance_lock`~~ —
  จอเดิมไม่แตะสักตัว (ยังเหลือเป็น `QUEUE_SOURCE=charges/bill/selfpay` ให้เลือกได้)
- ~~`QUEUE_MAX_AGE_MINUTES=240`~~ — ปิดเป็นค่าเริ่มต้น (0) ไม่ต้องใช้แล้ว
- ~~เรียงด้วย `pt_priority`~~ — จอเดิมใช้ทำสีจุด ไม่ได้ใช้เรียง

## ห้องเก็บเงินไม่มีเลขคิวของตัวเอง — ยืนยันจากตาราง serial

HOSxP ออกเลขคิวรายแผนกผ่านตาราง `serial` ด้วย key `ovst-dep-q-<depcode>-<yymmdd>`
(ค่าใน `serial_no` = ออกไปแล้วกี่คิวของวันนั้น) ดูของจริงวันที่ 2 ก.ย. 2569

| depcode | แผนก | คิวที่ออกวันนั้น |
| --- | --- | --- |
| `001` | ซักประวัติ | 71 |
| `019` | ทันตกรรม | 29 |
| `026` | คลีนิครวมน้ำใจ | 28 |
| `014` | คลินิก ANC | 22 |
| **`013`** | **ห้องเก็บเงิน** | **ไม่มีเลย** |

ย้อนหลังทั้งปี `ovst-dep-q-013-*` ขึ้นสูงสุดแค่ **1–2 คิวต่อวัน** = ไม่ได้ใช้งานจริง

**สรุป: ห้องเก็บเงินไม่ได้ออกเลขคิวของตัวเอง** จึงต้องใช้ `ovst.oqueue`
(เลขคิวของ visit ที่ออกตอนลงทะเบียน ใช้ร่วมทั้งโรงพยาบาล) ตามที่ทำอยู่
— ตรงกับที่จอเดิมของ รพ. ปล่อยคอลัมน์ "คิว" ว่างไว้ เพราะไม่มีเลขให้แสดง

### ตารางอื่นที่ตรวจแล้ว ไม่ต้องใช้

| ตาราง | เจออะไร | ใช้ไหม |
| --- | --- | --- |
| `serial` | ตัวนับเลขรันของ HOSxP · `ovst-dep-q-*` เลขคิวรายแผนก · `ipt-rx-queue-*` คิวยา IPD | ❌ ไม่มีคิวห้องเก็บเงิน |
| `spclty` | รหัสแผนกเฉพาะทาง (`18` = กลับบ้าน) | ❌ ชื่อแผนกใช้จาก `kskdepartment` อยู่แล้ว |
| `patient` | `pname` / `fname` / `lname` — คำนำหน้ามีทั้ง นาง · น.ส. · ด.ช. · ด.ญ. · พระ | ✅ ใช้อยู่แล้ว (ปิดบังเฉพาะนามสกุล) |

## ยกตรรกะ "ออกจากระบบแล้ว" มาจาก dept-status ของ ppc-hos-10667

หน้า dept-status ของโปรเจกต์พี่น้อง (`lib/deptStatus.service.ts`) มีลิสต์ keyword
ของชื่อสถานะที่ถือว่าผู้ป่วยออกจาก flow OPD แล้ว — เอามาใช้กับจอคิวห้องเก็บเงินด้วย
เพราะคนกลุ่มนี้ไม่มีทางกลับมาจ่ายเงิน แต่ `cur_dep` อาจยังค้างที่ `013` อยู่

จับคู่กับ `ovstost` จริงของ รพ. (28 สถานะ) ได้ผลดังนี้

| ตัดออกจากจอ | คงอยู่บนจอ |
| --- | --- |
| `Admit แผนก…` (ทุกแผนก) | `รอผลตรวจ` |
| `หนีกลับ` | `ตรวจแล้ว` |
| `ปฏิเสธการรักษา` | `รอรับยา` |
| `เสียชีวิต` / `เสียชีวิตก่อนมาถึง…` / `เสียชีวิตระหว่างส่งต่อ…` | `ตรวจรักษาที่แผนก` |
| `ตายที่แผนกผู้ป่วยนอก` | `ตรวจรักษาที่แผนกส่งเสริมสุขภาพ` |
| `ส่งต่อสถานพยาบาลอื่น` | `ตรวจรักษาที่ห้อง ER` |

**`หนีกลับ` กับ `ปฏิเสธการรักษา` คือตัวที่ได้ประโยชน์จริง** — เดิมคนกลุ่มนี้จะค้างบนจอ
จนกว่าตัวตัดเวลา 240 นาทีจะทำงาน ตอนนี้หลุดทันทีที่เจ้าหน้าที่บันทึกสถานะ

⚠️ ห้ามใส่คำว่า `แล้ว` เข้าไปในลิสต์ จะไป match `ตรวจแล้ว` ซึ่งยังต้องมาจ่ายเงิน
ปรับลิสต์ได้ที่ env `FINISHED_STATUS`

### สิ่งที่ไม่ได้เอามาจาก dept-status

| ของ dept-status | ทำไมไม่เอามา |
| --- | --- |
| ไม่กรอง `an IS NULL` | เขาต้องนับคน Admit เป็น "เสร็จ" แต่จอคิวเราต้องตัดออก |
| `cachedQuery` TTL 60 วิ | จอคิวรีเฟรชทุก 15 วิ ถ้า cache 60 วิจะเห็นข้อมูลเก่า |
| เรียงตาม `vsttime` | จอเราเรียงตามเลขคิว `oqueue` ตามที่หน้างานกำหนด |
| การ์ดสรุปรายแผนก / Donut | คนละงาน จอเราแสดงรายชื่อคิวอย่างเดียว |
