# ห้องเก็บเงินแดง — cashier_dashboard

จอคิวห้องการเงิน **สำหรับคนไข้ดู** ดึงรายชื่อคนที่ถูกส่งมาชำระเงินตาม flow ผู้ป่วยนอก
จาก **HOSxP (MySQL)** ขึ้นจอทีวีหน้าห้อง พร้อม **ประกาศเรียกชื่ออัตโนมัติ** (เสียงไทย)

> **ไม่มีอะไรให้กดทั้งระบบ** — เจ้าหน้าที่ทำงานใน HOSxP ตามปกติ
> จอแค่ตามข้อมูลจาก HOSxP แล้วขึ้น/ประกาศให้เอง คนไข้มีหน้าที่ดูอย่างเดียว

> 📄 เกณฑ์ว่า "ใครนับเป็นคิวห้องการเงิน" ยึดตาม **[docs/OPD_FLOW.md](docs/OPD_FLOW.md)**
> — flow เปลี่ยนเมื่อไหร่ ให้แก้เอกสารนั้นกับ `lib/cashier.service.ts` คู่กัน

## จอในระบบ

| URL | ใช้ที่ไหน | เห็นอะไร |
| --- | --- | --- |
| **`/`** | **ทีวีหน้าห้องการเงิน** | คิว 10 คน แยก 2 ช่อง ช่องละ 5 + ประกาศเรียกชื่อ |
| `/display` | จอที่สอง (ถ้ามี) | ชื่อคนที่ถึงคิว คนเดียวเต็มจอ ตัวใหญ่สุด |

ทั้งสองจอ **ไม่มี VN/HN** และ **ปิดบังนามสกุล** — `/tv` (URL เดิม) ยังใช้ได้ ระบบจะพาไป `/` ให้

## Deploy ด้วย Docker (ใช้งานจริง)

```bash
# 1) ตั้งค่า env
cp .env.example .env.production
nano .env.production        # ใส่ DB_HOST / DB_USER / DB_PASS / DB_NAME ของ HOSxP

# 2) build + รัน
docker compose up -d --build

# 3) เปิดใช้งาน
#    http://<ip-เครื่อง>:4500          → จอคิว (เปิดเต็มจอ F11 บนทีวี)
#    http://<ip-เครื่อง>:4500/display  → จอเรียกชื่อ (จอที่สอง ถ้ามี)
```

คำสั่งที่ใช้บ่อย

```bash
docker compose logs -f app     # ดู log
docker compose restart app     # รีสตาร์ต
docker compose down            # หยุด
docker compose up -d --build   # deploy เวอร์ชันใหม่หลังแก้โค้ด
```

### เรื่องพอร์ต 4500

พอร์ตถูกตั้งไว้ 3 ที่ ให้ตรงกันเสมอ — ถ้าจะเปลี่ยนต้องแก้ทั้งสามที่:

| ไฟล์ | บรรทัด |
| --- | --- |
| `Dockerfile` | `EXPOSE 4500` / `ENV PORT=4500` |
| `docker-compose.yml` | `ports: - "4500:4500"` และ healthcheck |
| `package.json` | `next dev -p 4500` / `next start -p 4500` |

ถ้าอยากเปลี่ยนเฉพาะพอร์ตฝั่ง host (เข้าเว็บทางพอร์ตอื่น แต่ใน container ยังเป็น 4500)
แก้แค่ `docker-compose.yml` เป็น `"8080:4500"` พอ

### หมายเหตุตอน build

- เครื่องที่ build **ต้องต่อเน็ตได้** เพราะ `next/font/google` โหลดฟอนต์ Sarabun ตอน build
- ค่า env ของ DB **ไม่จำเป็นตอน build** — `lib/db.ts` สร้าง connection pool แบบ lazy ตอน runtime
  จึงเปลี่ยน `.env.production` แล้ว `docker compose restart` ได้เลย ไม่ต้อง build ใหม่

## การเชื่อมต่อ HOSxP

ตั้งค่าใน `.env.production` (ดูคำอธิบายทุกตัวใน [`.env.example`](.env.example))

| ตัวแปร | ความหมาย |
| --- | --- |
| `DB_HOST` | IP เครื่อง HOSxP — ถ้า MySQL อยู่บนเครื่อง host เดียวกับ docker ใช้ `host.docker.internal` |
| `DB_PORT` `DB_USER` `DB_PASS` `DB_NAME` | ค่าเชื่อมต่อ MySQL (ใช้ user ที่มีสิทธิ์ **อ่านอย่างเดียว** ก็พอ) |
| `CASHIER_DEP_CODES` | รหัสแผนกห้องเก็บเงิน (`kskdepartment.depcode`) คั่นด้วย comma |
| `HOSPITAL_NAME` | ชื่อ รพ. ที่โชว์บนหัวจอและจอเรียกชื่อ |
| `REFRESH_SECONDS` | ระยะรีเฟรชอัตโนมัติ (ค่าเริ่มต้น 15 วินาที) |
| `BOARD_TITLE` | ชื่อที่ขึ้นหัวจอ (ค่าเริ่มต้น `ห้องเก็บเงินโรงพยาบาลพลับพลาชัย`) |
| `BOARD_ROWS` | จำนวนแถวใน "คิวรอ" ไม่นับคนที่กำลังเรียก (ค่าเริ่มต้น 10) |
| `BOARD_ROWS_PER_COLUMN` | แบ่งเป็นช่อง ช่องละกี่คิว (ค่าเริ่มต้น 5 → 10 คิว = 2 ช่อง) |

| `DEMO_MODE=1` | บังคับใช้ข้อมูลตัวอย่าง (ไว้สาธิต/อบรม) |

**โหมดสาธิต:** ถ้ายังไม่ได้ตั้ง `DB_HOST/DB_USER/DB_PASS/DB_NAME` ครบ ระบบจะขึ้นข้อมูลตัวอย่างพร้อมแถบเตือน
สีเหลือง — เปิดดูหน้าจอได้ทันทีตั้งแต่ `docker compose up` ครั้งแรก แล้วค่อยเติมค่า DB ทีหลัง

### หา `CASHIER_DEP_CODES` และตรวจข้อมูลก่อนใช้จริง

เปิด [`docs/sql/cashier_queue.sql`](docs/sql/cashier_queue.sql) รันใน HeidiSQL/MySQL client:

1. ข้อ 1 — หา `depcode` ของแผนกห้องเก็บเงิน → เอาไปใส่ `CASHIER_DEP_CODES`
2. ข้อ 3 — รัน query เดียวกับที่แอปยิง ดูว่าได้รายชื่อครบไหม
3. ข้อ 4.1 — เช็กว่าคนที่ยังตรวจไม่เสร็จ **ไม่** หลุดเข้ามาในคิว
4. ข้อ 5 — กระทบยอดรวมกับรายงานการเงินของวัน

**ถ้าไม่ตั้ง `CASHIER_DEP_CODES`** ระบบจะเดาจากเวลาจุดบริการใน `service_time` แทน
(ไม่มียา = ตรวจเสร็จแล้ว · มียา = ถึงห้องยาแล้ว) ซึ่ง**หลวมกว่า** เพราะคนมียาจะขึ้นคิว
ตั้งแต่เพิ่งถึงห้องยาทั้งที่อาจยังจัดยาไม่เสร็จ — รู้ depcode แล้วให้ตั้งทันที
รายละเอียดใน [docs/OPD_FLOW.md](docs/OPD_FLOW.md)

### ใครเข้าคิวห้องการเงินบ้าง (ตาม flow)

| flow | เข้าคิวไหม |
| --- | --- |
| ยังไม่ผ่านแพทย์ (Pre-reg / Triage / ห้องบัตร / ซักประวัติ / หน้าห้องตรวจ) | ❌ ยังไม่ใช่คิวการเงิน |
| **Admit → Ward** | ❌ flow จบที่ ward (`o.an IS NULL` ตัดออก) |
| **ไม่มียา** → ส่งมาห้องการเงินหลังตรวจเสร็จ | ✅ |
| **มียา** → ห้องยาจัดยา → **ส่งรายชื่อ** มาห้องการเงิน | ✅ (เข้าคิว *หลัง* ผ่านห้องยา ไม่ใช่ทันทีที่ตรวจเสร็จ) |
| **ER** → HosXP ส่งบริการ → มียา/ไม่มียา | ✅ |

คอลัมน์ **"ไปต่อ"** บนคอนโซล (และป้ายบนจอ TV) บอกเส้นทางหลังชำระเงินตาม flow —
`🏠 กลับบ้าน` สำหรับคนไม่มียา, `💊 ห้องยา` สำหรับคนมียาที่ต้องกลับไปรับยาต่อ

### เกณฑ์แปลงสถานะ

| สถานะบนจอ | เงื่อนไข |
| --- | --- |
| คิวรอ | `ovst.cur_dep IN (013,077,078)` **และยังไม่ถูกเรียก** (ไม่มีแถวใน `sd_queue_calling`) |
| เรียกคิว | 2 แถวล่าสุดของวันนี้ใน `sd_queue_calling` เรียงตามเวลาที่กดเรียก |

เจ้าหน้าที่กด **"เรียกคิว" ใน HOSxP** → มีแถวใหม่ใน `sd_queue_calling` →
คนนั้นย้ายจาก "คิวรอ" ขึ้นไปอยู่ "เรียกคิว" และจอประกาศชื่อให้เอง

★ **ทั้งหมดนี้ยกมาจากซอร์สโค้ดจอเดิมของ รพ. ตรง ๆ** (`moneyAndDrug.php` +
`ajax/getScreeningW.php` + `ajax/getDoctorRoomQ.php`) ไม่ใช่การเดาจากโครงสร้างตาราง
รายละเอียดพร้อม SQL เต็มอยู่ใน [docs/OPD_FLOW.md](docs/OPD_FLOW.md)

โหมดเริ่มต้น (`QUEUE_SOURCE=all`) **ไม่แตะตารางการเงินเลย** เหมือนจอเดิม —
ไม่ใช้ยอดเงิน ไม่ใช้ `finance_lock` / `remain_money` / `paidst` / `rx_operator`

**ลำดับคิวรอ** = `ovst.cur_dep_time` (เวลาที่ถูกส่งมาห้องเก็บเงิน) จากเก่าไปใหม่
เหมือน `ORDER BY o.cur_dep_time asc` ของจอเดิมเป๊ะ ๆ

จอนี้ **ไม่มีปุ่มให้กดเลย** ทั้งจอ และ **ไม่เขียนกลับ HOSxP** — จอเดิมจะ `UPDATE
sd_queue_calling_status='N'` หลังประกาศเสียง จอนี้ไม่เขียน จะได้รันคู่กับจอเดิม
ได้โดยไม่แย่งกัน

> แอปนี้อ่านข้อมูลอย่างเดียว (`SELECT`) ไม่มีคำสั่งเขียนใด ๆ ไปที่ฐานข้อมูล HOSxP

### แผนกห้องเก็บเงิน = `013,077,078`

ห้องเก็บเงินมี **3 จุดบริการ** — ชุดเดียวกับที่จอเดิมส่งเข้า ajax
(`moneyAndDrug.php` บรรทัด 291–292) ตั้งเป็นค่าเริ่มต้นในโค้ดให้แล้ว

```
CASHIER_DEP_CODES=013,077,078
```

จอจะเอาเฉพาะคนที่ HosXP **ส่งมาอยู่ห้องเก็บเงินตอนนี้** (`ovst.cur_dep`)
ซึ่งทำให้ **"เวลาส่ง" เป็นเวลาที่ถูกส่งมาห้องเก็บเงินจริง ๆ** (`ovst.cur_dep_time`)
และ **"แผนกที่ส่ง" เป็นแผนกก่อนหน้า** (`ovst.last_dep`) เช่น ห้องยา / ทันตกรรม

**จอว่างตอนเช้าเป็นเรื่องปกติ** — ก่อนที่คนแรกจะพบแพทย์เสร็จแล้วถูกส่งมาห้องเก็บเงิน
จอจะขึ้น "ยังไม่มีคิวชำระเงิน" ไม่ใช่ความผิดพลาด (ห้ามให้ระบบไปเอาคนที่เพิ่งลงทะเบียน
มาขึ้นแทน เพราะคนกลุ่มนั้นยังไม่ได้พบแพทย์เลย)

รหัสแผนกอื่นที่เกี่ยวข้อง: `008` ห้องยา · `060/061` จ่ายยา ก/ข · `029` กลับบ้าน · `009` ห้องฉุกเฉิน

### เลือกว่าใครขึ้นจอ (`QUEUE_SOURCE`)

| ค่า | ใครขึ้นจอ | อ่านจาก |
| --- | --- | --- |
| **`all`** (ค่าเริ่มต้น) | ผู้ป่วยนอกทุกคนของวันนี้ | `ovst` |
| `charges` | คนที่มีค่าใช้จ่ายและยังไม่ปิดยอด | `opitemrece` + `ovst.finance_summary_date` |
| `bill` | คนที่มีบิลและยังไม่ถูกเคลียร์ | `opd_opi_finance_summary.balance_amount` |
| `selfpay` | เฉพาะคนที่ควักเงินจ่ายเอง | `total_balance_01 + total_balance_03` |

**แนะนำ: เริ่มที่ `all` ให้เห็นชื่อก่อน** แล้วค่อยไล่กรองให้แคบลงทีละขั้นจนตรงกับจอเดิม
เปลี่ยนแล้ว `docker compose restart app` พอ ไม่ต้อง build ใหม่

ถ้าเกณฑ์ที่ตั้งไม่ได้คนเลย ระบบจะ**ถอยไปใช้เกณฑ์ที่หลวมกว่าให้อัตโนมัติ** จอทีวี
จะได้ไม่ว่างเปล่าทั้งที่มีคนไข้รออยู่ — `/api/queue/debug` บอกว่าสุดท้ายใช้เกณฑ์ไหน
(`queueSourceUsed`)

### คนที่จ่ายเงินไปแล้วยังค้างบนจอ

แปลว่า HOSxP ไม่ได้อัปเดตสัญญาณ "ปิดยอด" ที่จอเราอ่าน จอเช็ค **2 ทาง** อยู่แล้ว

1. `ovst.finance_summary_date` ถูกใส่ = ปิดยอดแล้ว
2. มีแถวใน `opd_opi_finance_summary` แล้วยอดคงเหลือหมด = รับเงินแล้ว

ถ้า รพ. ไม่ได้ใช้ทั้งสองทาง จะมี **ตัวกันค้างตามเวลา** รับไว้อีกชั้น —
ถูกส่งมานานเกิน `QUEUE_MAX_AGE_MINUTES` (ค่าเริ่มต้น 120 นาที) จะหลุดจากจอเอง

อยากให้หลุดเร็วขึ้น ลดเป็น 60 หรือ 45 ได้

```
QUEUE_MAX_AGE_MINUTES=60
```

เปิด `/api/queue/debug` ดูบรรทัด `4b_bill_เคลียร์แล้ว` กับ `5c_all_ยังไม่ปิดยอด`
จะรู้ว่า รพ. ใช้สัญญาณไหนอยู่จริง

### จอว่าง ไม่มีรายชื่อ ทำยังไง

เปิด **`http://<ip-เครื่อง>:4500/api/queue/debug`** จะบอกจำนวนคนที่เหลือในแต่ละขั้นของ
การกรอง พร้อมเดาสาเหตุให้ เช่น

```json
{
  "queueSource": "bill",
  "counts": {
    "1_visit_วันนี้ทั้งหมด": 264,
    "2_ตัด_admit_ออก": 260,
    "3_มีแถวใน_finance_summary": 0,      ← หายตรงนี้
    "4a_bill_ยังไม่เคลียร์": 0,
    "7_ที่จอเห็นตอนนี้": 0
  },
  "hint": "ไม่มีแถวใน opd_opi_finance_summary ของวันนี้เลย ..."
}
```

แก้ตามที่มันหาย

| หายตรงขั้น | แปลว่า | ทำยังไง |
| --- | --- | --- |
| 1 = 0 | วันนี้ยังไม่มี visit | เช็ควันที่/TZ ของเครื่อง |
| 3 = 0 | `opd_opi_finance_summary` ยังไม่มีข้อมูลของวันนี้ | บอกผม จะเปลี่ยนไปนับจาก `opitemrece` แทน |
| 4a = 0 แต่ 5a > 0 | ทุกคนเคลียร์บิลแล้ว เหลือแต่คนจ่ายเอง | ตั้ง `QUEUE_SOURCE=selfpay` |
| 5a = 0 แต่ 4a > 0 | คนส่วนใหญ่ใช้สิทธิ์ ไม่ได้ควักจ่ายเอง | ใช้ `QUEUE_SOURCE=bill` (ค่าเริ่มต้น) |
| 7 = 0 ทั้งที่ 4a/5a > 0 | ติดตัวกรองแผนก | ลบ `CASHIER_DEP_CODES` ออกจาก env |

เปลี่ยน env แล้ว `docker compose restart app` พอ ไม่ต้อง build ใหม่

## จอคิวหน้าห้องการเงิน (`/`)

เปิด `http://<ip-เครื่อง>:4500` แบบเต็มจอ (กด F11) บนทีวี — ออกแบบไว้ที่ **55 นิ้ว 1080p
ดูจากระยะ 4–6 เมตร**

- แบ่ง 2 ส่วนเหมือนจอเดิมของ รพ.
  - **เรียกคิว** ด้านบน — 2 คนล่าสุดที่ห้องเก็บเงินกดเรียก คนบนสุดตัวใหญ่ + เรืองแสง
    เป็นจังหวะ และเลื่อนเข้าเวลาเปลี่ยนคน (สะดุดตาจากท้ายห้อง)
  - **คิวรอ** ด้านล่าง — โทนเขียวมิ้น แยก **2 ช่อง ช่องละ 5 คิว**
- **เลขคิว** = `ovst.oqueue` เลขเดียวกับจอคิวเดิม มีป้าย "คิว" กำกับกันสับสนกับลำดับที่
- **"ที่ 1 … ที่ 10"** บอกคนไข้ว่าอีกกี่คิวถึงตัวเอง
- **ทุกค่ามีป้ายกำกับ** คนไข้อ่านแล้วรู้ทันทีว่าตัวเลข/ชื่อแผนกนั้นคืออะไร

  | ส่วน | แสดง | ความหมาย |
  | --- | --- | --- |
  | คิวรอ | `ส่งมา 09:28 · จาก ห้องตรวจ` | แผนกที่ **ส่งคนไข้มา** (`ovst.last_dep`) |
  | เรียกคิว | `เรียก 09:41 · ไปที่ ห้องเก็บเงิน` | จุดที่ **ต้องเดินไป** (แผนกที่กดเรียก) |

  ⚠️ สองที่นี้ความหมายต่างกัน ห้ามใช้คำเดียวกัน — ถ้าเขียน "มาจาก" ทั้งคู่
  คนที่ถูกเรียกจะอ่านเป็น "มาจากห้องเก็บเงิน" แล้วนั่งรอต่อแทนที่จะเดินไปจ่ายเงิน
- **"รอ 12 นาที"** เวลารอจริง คิดจากเวลาที่ถูกส่งมา
  (จอเดิมมีช่องนี้เหมือนกัน แต่เป็นเลขปลอม `180 × ลำดับ ÷ 60`)
- **เรียงตามเวลาที่ถูกส่งมาห้องเก็บเงิน** (`cur_dep_time`) เหมือนจอเดิม ไม่ได้เรียงตามเลขคิว
- หัวข้อ "คิวรอ" มีป้ายจำนวนคนรอทั้งหมดกำกับ
- **พอถูกเรียก แถวนั้นหลุดจากคิวรอเอง คนถัดไปเลื่อนขึ้นมาแทน** (รีเฟรชทุก `REFRESH_SECONDS` วินาที)
- ท้ายจอบอกจำนวนที่รอทั้งหมด + จำนวนที่ยังไม่ได้ขึ้นจอ + เรียกไปแล้ววันนี้
- จุดแดงข้างนาฬิกา = ดึงข้อมูลรอบล่าสุดไม่สำเร็จ (ตัวเลขบนจอเป็นของเก่า) จอจะไม่ว่าง
- เคารพ `prefers-reduced-motion` ของระบบ — ปิดการเคลื่อนไหวให้อัตโนมัติ

**ไอคอนเป็น SVG ฝังในโค้ด ไม่ใช่ emoji** (`app/Icon.tsx`) เพราะ emoji หน้าตาต่างกัน
ทุกเครื่อง คุมสีไม่ได้ และกลายเป็นสี่เหลี่ยมเปล่า □ ถ้ากล่องทีวีไม่มีฟอนต์ emoji
ไอคอนชุดนี้ใช้ `currentColor` จึงเปลี่ยนสีตามข้อความรอบตัว และคมทุกขนาดเพราะเป็น vector
เพิ่ม/แก้ไอคอนแผนกได้ที่ `app/dept.ts` (จับด้วย keyword ของชื่อแผนก)

**วัดจริงบน 1920×1080 แล้ว: `scrollHeight = 1080` พอดี ไม่มี scroll ไม่มีของตกขอบ**
ทุกขนาดคิดเป็นหน่วย `vh` จอ 4K จึงขยายตามเองโดยไม่ต้องแก้อะไร

### ไม่มีอะไรให้กด

ทั้งระบบไม่มีปุ่มที่ต้องกดเลย เจ้าหน้าที่รับเงินใน HOSxP ตามปกติ จอจะเห็นเองว่า
คนนั้นจ่ายครบแล้ว → เอาออกจากคิว → เลื่อนคนถัดไปขึ้นมา → ประกาศชื่อคนใหม่

### เสียงเรียกคิว

จอ `/` จะ **ประกาศชื่อเองอัตโนมัติ** ทุกครั้งที่มีคนถูกกดเรียกใหม่ใน HOSxP
(พูด 1 ครั้งต่อการเรียก 1 ครั้ง ไม่พูดซ้ำ)

**เลือกเสียงด้วย `TTS_VOICE`** — ค่าเริ่มต้นคือ `Siri` ใส่แค่บางส่วนของชื่อก็พอ

```
TTS_VOICE=Siri
```

ชื่อเสียงขึ้นกับ OS ของ **เครื่องที่ต่อกับจอ TV** ไม่ใช่เครื่อง server:

| เครื่องที่ต่อจอ | เสียงไทยที่มักมี |
| --- | --- |
| iPad / Mac / Apple TV (Safari) | `Siri`, `Kanya` |
| Windows (Chrome / Edge) | `Premwadee`, `Pattara`, `Narisa` |
| Android / Chrome OS | เสียงไทยของ Google |

หาเสียงที่ตั้งไว้ไม่เจอ ระบบจะไล่หาเสียงไทยตัวอื่นให้เอง **ไม่ปล่อยให้เงียบ**

👉 **เปิด `http://<ip>:4500/voices` บนเครื่องที่ต่อจอ** จะเห็นรายชื่อเสียงที่เครื่องนั้น
มีจริง พร้อมปุ่มกดฟังตัวอย่าง แล้วเอาชื่อไปใส่ `TTS_VOICE`
อยากลองสดบนจอก่อนก็ต่อท้าย URL ได้เลย: `http://<ip>:4500/?voice=premwadee`

⚠️ Windows ที่ยังไม่มีเสียงไทย ลงเพิ่มได้ที่
Settings → Time &amp; language → Speech → Add voices → ไทย

**ข้อจำกัดของเบราว์เซอร์:** เบราว์เซอร์ไม่ยอมเล่นเสียงจนกว่าหน้าเว็บจะเคยถูกแตะ 1 ครั้ง
จอจะขึ้นแถบ *"แตะหน้าจอหนึ่งครั้งเพื่อเปิดเสียงเรียกคิว"* — แตะครั้งเดียวตอนเปิดจอตอนเช้าแล้วจบ

อยากให้ไม่ต้องแตะเลย เปิด Chrome แบบ kiosk ด้วยแฟลกนี้ (ใส่ใน shortcut ที่ startup)

```
chrome.exe --kiosk --autoplay-policy=no-user-gesture-required http://<ip>:4500
```

**เปิดหลายจอในห้องเดียวกัน** ให้จอที่ไม่ต้องมีเสียงต่อ `?sound=0` ท้าย URL
(เช่น `http://<ip>:4500/display?sound=0`) กันเสียงประกาศซ้อนกัน

### ความเป็นส่วนตัว

จอตั้งในที่สาธารณะ จึง **ไม่ส่ง VN/HN ลงมาที่เบราว์เซอร์เลย** และ **ปิดบังนามสกุล**
ตั้งแต่ฝั่ง server (`/api/queue` + `lib/mask.ts`) — เช่น
`นางสาวพัชรี สดชื่น` → `นางสาวพัชรี ส●●●●`

`/api/queue/call` (ที่ใช้ประกาศเสียง) ส่งชื่อเต็มเพราะต้องอ่านออกเสียง แต่ก็ยังไม่มี VN/HN

### ปรับจำนวนคิว / จำนวนช่อง

ตั้งใน `.env.production` — ความสูงแถวคำนวณเองอัตโนมัติ ไม่ต้องแก้ CSS

| อยากได้ | ตั้งค่า |
| --- | --- |
| 10 คิว 2 ช่อง (ค่าเริ่มต้น) | `BOARD_ROWS=10` `BOARD_ROWS_PER_COLUMN=5` |
| 12 คิว 2 ช่อง ช่องละ 6 | `BOARD_ROWS=12` `BOARD_ROWS_PER_COLUMN=6` |
| 15 คิว 3 ช่อง ช่องละ 5 | `BOARD_ROWS=15` `BOARD_ROWS_PER_COLUMN=5` |
| ช่องเดียวยาว 10 คิว | `BOARD_ROWS=10` `BOARD_ROWS_PER_COLUMN=10` |

ยิ่งเพิ่มคิวต่อช่อง แถวยิ่งเตี้ยลง (ตัวอักษรคงเดิม) — เกินช่องละ ~7 คิวบนจอ 1080p
เริ่มแน่น ถ้าอยากได้เยอะกว่านั้นให้เพิ่ม *ช่อง* แทนการเพิ่มคิวต่อช่อง

### สีของจอ

จอตั้ง token สีของตัวเองไว้ครบในคลาส `.tv` / `.display-screen` (ไฟล์ `app/globals.css`)
จึงเป็นเขียวมิ้นเสมอ ไม่เปลี่ยนตามธีมมืด/สว่างของเบราว์เซอร์ที่เสียบกับทีวี
อยากปรับเฉด แก้ตัวแปร `--tv-*` ตรงหัวบล็อกนั้นที่เดียว
